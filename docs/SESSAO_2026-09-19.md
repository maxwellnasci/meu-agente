# Sessão 2026-09-19 — Homologação multi-tenant na Contabo e ajustes finos do provisionador

Data: 2026-09-19.
Escopo: homologação do primeiro cliente provisionado via
`scripts/provision-client.sh` em produção (Contabo), correções do Cão de
Guarda, auditoria do Revisor e ajustes finos (compose sem `build`
relativo, asserções de rede, recarga de `.env`).

## 1. Homologação do cliente-teste na Contabo

- **Instância**: cliente-teste provisionado localmente com
  `scripts/provision-client.sh` e copiado para o diretório operacional
  isolado no host de produção
  (`/root/meu-agente-clientes/deployments/<slug>/`, fora da árvore
  sincronizada via `rsync --delete` — ver §6.1 de
  [PADRAO_CLIENTES_DOCKER.md](PADRAO_CLIENTES_DOCKER.md)).
- **Porta**: `ORCHESTRATOR_HOST_PORT=8015`, publicada só em loopback
  (`127.0.0.1:8015:8000`).
- **Isolamento de rede**: rede bridge dedicada `cliente-teste-net`
  (1 rede por tenant, sem visibilidade cruzada entre clientes).
- **Saúde**: `GET /health` → HTTP 200; `POST /v1/turn` com `session_key`
  de smoke retornando `reply_text`.
- **Desligamento limpo**: `docker compose down` removeu container + rede
  do cliente-teste sem tocar nos demais serviços.
- **Integridade da produção**: os 8 containers de produção seguiram
  intactos e saudáveis após o ciclo completo sobe/valida/desce.

## 2. Correções do Cão de Guarda

1. **`curl` → `urllib.request` nativo**: o `healthcheck` do compose
   gerado usava `curl`, ausente na imagem `python:3.11-slim` (ver
   `orchestrator/Dockerfile`). Trocado por teste Python nativo:
   `["CMD", "python", "-c", "import urllib.request as u;
   u.urlopen('http://127.0.0.1:8000/health', timeout=3)"]` — zero
   dependência externa dentro do container.
2. **Injeção silenciosa da chave OpenRouter sem conflito de
   stdin/`EOFError`**: a cópia da chave (`ORCHESTRATOR_OPENROUTER_API_KEY`)
   para o `.env` do cliente no host passou a usar leitura silenciosa
   (`read -rs ... < /dev/tty`) + script Python via heredoc com argumento
   de caminho (`python3 - "$PWD/.env" <<'EOF'`), eliminando o conflito de
   stdin que gerava `EOFError` e a injeção silenciosa/falha sem mensagem.

## 3. Auditoria do Revisor

- **Validação funcional de liveness**: checagem de `/health` com
  distinção de códigos de erro HTTP vs. erros de rede (falha de conexão
  ≠ resposta não-200), para diagnóstico preciso em produção.
- **Testes mutacionais de regressão**: mutações aplicadas no código do
  provisionador/compose gerado para confirmar que a suíte
  (`orchestrator/tests/test_provision_client.py`) detecta regressões —
  nenhum mutante sobreviveu sem ser pego pelos testes.

## 4. Ajustes finos (pós-auditoria)

1. **Compose do cliente sem `build` relativo**
   (`scripts/provision-client.sh`): removida a diretiva
   `build: ../../orchestrator` do `docker-compose.yml` gerado — o serviço
   depende puramente da imagem pré-compilada
   (`image: ${ORCHESTRATOR_IMAGE:-meu-agente-orchestrator:local}`).
   Motivo: em diretório isolado de produção (ex.
   `/root/meu-agente-clientes/deployments/<slug>/` na Contabo) o caminho
   relativo `../../orchestrator` não existe e `docker compose up --build`
   falhava; com a remoção, o deploy sobe de primeira com
   `docker compose up -d`. Cabeçalho do compose gerado atualizado de
   `docker compose up -d --build` para `docker compose up -d`.
2. **Asserções de rede blindadas** (`test_provision_clinica_end_to_end`
   em `orchestrator/tests/test_provision_client.py`):
   `driver == "bridge"` na rede dedicada, `list(service["networks"]) ==
   [net]` (exatamente uma rede — a do tenant), `"build" not in service` e
   `image` parametrizável verificada. Suíte: **48/48 passando (100%)**.
3. **Recarga de `.env` mandatória** (§6.2 de
   [PADRAO_CLIENTES_DOCKER.md](PADRAO_CLIENTES_DOCKER.md)): documentado que
   `restart` simples NÃO relê o `.env` — após injetar a chave OpenRouter,
   recriar com `docker compose up -d`. Verificação da chave refinada para
   `re.search(r"^ORCHESTRATOR_OPENROUTER_API_KEY=", text, re.M)`
   (ancorada no início da linha, ignora linhas comentadas).
4. **§6.1**: comando de subida em produção ajustado de
   `docker compose up -d --build` para `docker compose up -d`.
