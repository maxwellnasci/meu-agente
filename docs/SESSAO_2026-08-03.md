## Correções Aplicadas

### Correção 1 — Duplo Conector (Etapa 1)

**Ação (executada pelo Max no terminal local do Kali):**
```bash
sudo systemctl disable --now cloudflared
# Output: Removed '/etc/systemd/system/multi-user.target.wants/cloudflared.service'.
```

**Verificação pós-correção:**
```
CONNECTOR ID                         CREATED              ORIGIN IP
00ea6b92-9432-4be8-b656-68ab38e26f97 2026-08-02T22:43:45Z 158.220.125.233  ← único ativo ✅
```
Conector do Kali `c6933b9d` removido da lista. 100% do tráfego agora vai pro Contabo.

**Causa raiz:** `cloudflared.service` estava `enabled` no systemd do Kali.
Não foi desabilitado na Etapa 7 da migração (2026-08-02) — só foi dado `stop`,
não `disable`. Quando o notebook ligou, o serviço subiu automaticamente.

**Lição aprendida:** Ao fazer cutover de túnel Cloudflare, sempre rodar
`systemctl disable --now cloudflared` (não só `stop`) no host que está
sendo aposentado. Documentado em MANUTENCAO.md.

### Correção 2 — Model Fallback (Etapa 2)

O schema do OpenClaw suporta `{ primary, fallbacks[] }` na config de modelo
(confirmado em `zod-schema.agent-model.d.ts`).

**Backup criado antes da edição:**
```
/root/.openclaw/openclaw.json.bak-20260803-1934
```

**Diff aplicado no `/root/.openclaw/openclaw.json` no Contabo:**
```diff
  "agents": {
    "defaults": {
      "model": {
-       "primary": "deepseek/deepseek-chat"
+       "primary": "deepseek/deepseek-v4-flash",
+       "fallbacks": ["deepseek/deepseek-chat"]
      },
```

Edição feita via `python3` (parse + dump JSON, sem risco de corromper o arquivo).
Gateway reiniciado via `docker restart openclaw-openclaw-gateway-1`.

**Verificação pós-correção (`models status`):**
```
Default       : deepseek/deepseek-v4-flash
Fallbacks (1) : deepseek/deepseek-chat
```

Agora se o `v4-flash` der timeout, o OpenClaw automaticamente faz failover
para o `deepseek-chat` sem perder a mensagem.
